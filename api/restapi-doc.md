# Полное техническое описание REST API

## Общие сведения

- **Базовый URL**: `/api` (все эндпоинты доступны по префиксу `/api`)
- **Формат данных**: JSON (все запросы и ответы)
- **Кодировка**: UTF-8
- **Аутентификация**: JWT Bearer токен (передаётся в заголовке `Authorization: Bearer <token>`). Требуется для защищённых методов. Токен выдаётся при авторизации.
- **CORS**: Поддерживаются кросс-доменные запросы с любого источника (`*`), разрешены методы: GET, POST, PUT, PATCH, DELETE, HEAD, OPTIONS.
- **Пагинация**: Для методов, возвращающих списки, используется `ActiveDataProvider` с параметрами пагинации (по умолчанию `pageSize` = 50). Информация о пагинации передаётся в заголовках ответа:
  - `X-Pagination-Current-Page`
  - `X-Pagination-Page-Count`
  - `X-Pagination-Per-Page`
  - `X-Pagination-Total-Count`
- **Формат ответов**:
  - Успешные операции часто возвращают структуру `OkResponseDto`: `{ "success": true, "message": "...", "data": {...} }`
  - Ошибки возвращают `ErrorResponseDto`: `{ "success": false, "message": "...", "data": {...} }` (в `data` могут быть детали валидации или `null`)
  - Некоторые методы возвращают данные напрямую (без обёртки), особенно это касается стандартных REST действий, возвращающих модели или коллекции с пагинацией.

## Контроллеры и методы

### 1. AuthController

Контроллер аутентификации и профиля пользователя.

#### 1.1. POST /api/auth/login

Авторизация пользователя по логину/паролю.

- **Описание**: Выполняет вход, возвращает JWT токен.
- **Требует авторизации**: Нет.
- **Параметры запроса (body, JSON)**:
  ```json
  {
    "username": "логин или email",
    "password": "пароль"
  }
  ```
- **Ответ при успехе (200)**:
  ```json
  {
    "token": "string (JWT)",
    "tokenType": "Bearer",
    "expiresIn": 604800,
    "user": { ... } // данные пользователя (поля из User::toArray())
  }
  ```
- **Ошибки**:
  - `400` – ошибка валидации данных (не указаны обязательные поля) → `ErrorResponseDto`
  - `404` – пользователь не найден → `ErrorResponseDto`
  - `403` – неверный пароль → `ErrorResponseDto`

#### 1.2. POST /api/auth/signup

Регистрация нового пользователя.

- **Описание**: Создаёт нового пользователя, назначает роль "customer", выдаёт JWT токен.
- **Требует авторизации**: Нет.
- **Параметры запроса (body, JSON)**:
  ```json
  {
    "userName": "логин (обязательно)",
    "password": "пароль (мин. 6 символов, обязательно)",
    "email": "email (обязательно, уникальный)",
    "phone": "телефон (обязательно)",
    "name": "имя (обязательно)",
    "surname": "фамилия (обязательно)",
    "patronymic": "отчество (опционально)",
    "address": "адрес (опционально)",
    "dateOfBirth": "дата рождения (опционально, формат YYYY-MM-DD)",
    "image": "URL аватара (опционально, по умолчанию заглушка)"
  }
  ```
- **Ответ при успехе (200)**:
  ```json
  {
    "token": "string (JWT)",
    "tokenType": "Bearer",
    "expiresIn": 604800,
    "user": { ... } // данные пользователя
  }
  ```
- **Ошибки**: `422` – ошибка валидации (например, логин или email уже заняты) → `ErrorResponseDto` с деталями ошибок.

#### 1.3. GET /api/auth/me

Получить информацию о текущем авторизованном пользователе.

- **Описание**: Возвращает данные аутентифицированного пользователя.
- **Требует авторизации**: Да (Bearer токен).
- **Параметры**: Нет.
- **Ответ при успехе (200)**: данные пользователя (массив из `User::toArray()`).
- **Ошибка**: `403` – пользователь не авторизован → `ErrorResponseDto`.

#### 1.4. POST /api/auth/refresh

Обновить JWT токен.

- **Описание**: Генерирует новый токен для текущего пользователя.
- **Требует авторизации**: Да (Bearer токен).
- **Параметры**: Нет.
- **Ответ при успехе (200)**:
  ```json
  {
    "token": "string (новый JWT)",
    "tokenType": "Bearer",
    "expiresIn": 604800,
    "user": { ... }
  }
  ```
- **Ошибка**: `403` – пользователь не авторизован → `ErrorResponseDto`.

#### 1.5. OPTIONS /api/auth/options

Предварительный запрос CORS.

- **Описание**: Обрабатывает preflight запросы.
- **Требует авторизации**: Нет.
- **Ответ**: `{ "status": "ok" }`.

### 2. CategoryController

Управление категориями товаров.

Наследуется от `BaseApiController`, поэтому доступны стандартные REST действия: `index`, `view`, `create`, `update`, `delete`. Защищены запись/изменение/удаление (требуют администратора).

#### 2.1. GET /api/categories

Получить список категорий с пагинацией.

- **Описание**: Возвращает список всех категорий (по 50 на страницу).
- **Требует авторизации**: Нет.
- **Параметры query**:
  - `page` (int) – номер страницы
  - `per-page` (int) – количество на странице (по умолчанию 50)
  - `sort` (string) – поле сортировки (по умолчанию `id ASC`)
- **Ответ**: `ActiveDataProvider` со списком категорий (модели `Category`). Структура: `{ "items": [...], "_links": {...}, "_meta": {...} }` (формат сериализатора Yii2 с `collectionEnvelope: items`).

#### 2.2. GET /api/categories/{id}

Получить одну категорию по ID.

- **Требует авторизации**: Нет.
- **Параметры**: ID в URL.
- **Ответ**: модель `Category`.

#### 2.3. POST /api/categories

Создать новую категорию.

- **Требует авторизации**: Да (Bearer токен, роль администратора).
- **Параметры (body)**: поля модели `Category` (title, description, image и т.д., согласно модели).
- **Ответ**: созданная модель.

#### 2.4. PUT /api/categories/{id}

Обновить категорию.

- **Требует авторизации**: Да (администратор).
- **Параметры (body)**: обновляемые поля.
- **Ответ**: обновлённая модель.

#### 2.5. DELETE /api/categories/{id}

Удалить категорию.

- **Требует авторизации**: Да (администратор).
- **Ответ**: пустое тело с кодом 204.

#### 2.6. GET /api/categories/{id}/products

Получить все товары в указанной категории с пагинацией и фильтрацией.

- **Описание**: Возвращает товары, принадлежащие категории.
- **Требует авторизации**: Нет.
- **Параметры пути**: `id` – ID категории.
- **Параметры query**:
  - `inStock` (0/1 или true/false) – фильтр по наличию.
  - `sort` (string) – сортировка:
    - `price_asc` – по цене по возрастанию
    - `price_desc` – по цене по убыванию
    - `popular` – по популярности (пока что по убыванию ID, т.е. новинки)
    - по умолчанию `id_desc`
- **Ответ**: `ActiveDataProvider` с товарами (модели `Product`), пагинация по 50 записей.

### 4. ProductController

Управление товарами. Наследуется от `BaseApiController`. Стандартные действия: `index`, `view`, `update` (стандартный update от ActiveController) — доступны всем на чтение, но запись защищена. Действия `create` и `delete` переопределены (см. ниже).

#### 4.1. GET /api/products

Список товаров с фильтрацией, поиском и пагинацией.

- **Требует авторизации**: Нет.
- **Параметры query**:
  - `categoryId` (int) – фильтр по категории.
  - `inStock` (0/1 или true/false) – фильтр по наличию.
  - `q` (string) – поисковый запрос (поиск по title, article, short_description, long_description, info).
  - `sort` – сортировка: `price_asc`, `price_desc`, `popular` (по убыванию ID), `title` (по названию). По умолчанию `id DESC`.
  - `page`, `per-page` – пагинация (по умолчанию 50).
- **Ответ**: `ActiveDataProvider` с товарами (модели `Product` с загруженными связями `categories` и `productImages`).

#### 4.2. GET /api/products/{id}

Получить один товар.

- **Требует авторизации**: Нет.
- **Ответ**: модель `Product` с загруженными связями.

#### 4.3. POST /api/products (переопределён)

Создание нового товара.

- **Требует авторизации**: Да (администратор).
- **Параметры (body, JSON)**: используется `CreateProductRequest` DTO:
  ```json
  {
    "title": "Название (обязательно)",
    "article": "Артикул",
    "shortDescription": "Краткое описание (обязательно)",
    "longDescription": "Подробное описание (обязательно)",
    "info": "Дополнительная информация (можно JSON или текст)",
    "price": 1234.56,
    "inStock": true/false,
    "ordersCount": 0,
    "mainImage": "base64-encoded image или {title, image}",
    "manufacturer": "Производитель",
    "country": "Страна",
    "categoryIds": [1, 2, 3],
    "images": [
      { "title": "название", "image": "base64..." },
      ...
    ]
  }
  ```
  Примечание: `mainImage` и `images` ожидаются в формате base64 (с префиксом data:image/...;base64 или без). При успехе сохраняются изображения в папку `uploads/products/`.
- **Ответ при успехе (200)**:
  ```json
  {
    "success": true,
    "message": "Товар успешно создан",
    "data": { ... (модель Product) }
  }
  ```
- **Ошибки**: `422` – ошибка валидации, `500` – ошибка сохранения.

#### 4.4. PUT /api/products/{id}

Обновление товара (стандартное действие, доступно администратору).

- **Требует авторизации**: Да (администратор).
- **Параметры (body)**: поля для обновления (все поля модели).
- **Ответ**: обновлённая модель.

#### 4.5. DELETE /api/products/{id} (переопределён)

Удаление товара вместе с файлами изображений.

- **Требует авторизации**: Да (администратор).
- **Параметры**: ID в URL.
- **Ответ**: `204 No Content` при успехе.
- **Ошибки**: `404` – товар не найден, `403` – недостаточно прав.

#### 4.6. GET /api/products/latest

Получить последние добавленные товары (для карусели).

- **Требует авторизации**: Нет.
- **Параметры query**:
  - `limit` (int, по умолчанию 10) – количество товаров.
- **Ответ**:
  ```json
  {
    "success": true,
    "count": 10,
    "items": [ ... (модели Product) ]
  }
  ```

#### 4.7. GET /api/products/popular

Получить популярные товары (по дате добавления, пока что аналогично latest).

- **Требует авторизации**: Нет.
- **Параметры query**:
  - `limit` (int, по умолчанию 10).
- **Ответ**: аналогично `latest`.

#### 4.8. GET /api/products/search

Быстрый поиск товаров для автодополнения.

- **Требует авторизации**: Нет.
- **Параметры query**:
  - `q` (string) – поисковый запрос (обязательный).
  - `limit` (int, по умолчанию 20) – максимальное количество результатов.
- **Ответ**:
  ```json
  {
    "success": true,
    "query": "запрос",
    "total": 5,
    "items": [ ... (модели Product) ]
  }
  ```

#### 4.9. POST /api/products/{id}/sync-categories

Синхронизация категорий товара (заменяет все существующие связи).

- **Требует авторизации**: Да (администратор).
- **Параметры пути**: `id` – ID товара.
- **Параметры body**:
  ```json
  {
    "categoryIds": [1, 2, 3]  // массив ID категорий
  }
  ```
- **Ответ**:
  ```json
  {
    "success": true,
    "message": "Категории товара успешно обновлены",
    "product": { ... } // модель товара
  }
  ```

#### 4.10. POST /api/products/{id}/images

Добавление изображения к товару (связь через ProductImage).

- **Требует авторизации**: Да (администратор).
- **Параметры пути**: `id` – ID товара.
- **Параметры body**:
  ```json
  {
    "image_id": 123,   // ID записи ImageEntity
    "title": "Название фото",
    "is_main": false   // опционально
  }
  ```
- **Ответ при успехе**:
  ```json
  {
    "success": true,
    "message": "Фотография добавлена в галерею товара",
    "data": { ... } // модель ProductImage
  }
  ```
- **Ошибки**: `422` – ошибки валидации.

### 5. ProductImageController

Управление связями товаров и изображений (ProductImage).

#### 5.1. GET /api/product-images

Получить список связей с фильтрацией.

- **Требует авторизации**: Нет (доступно всем на чтение? По коду только index не защищён, но в behaviors есть аутентификация только для create/update/delete).
- **Параметры query**:
  - `productId` (int) – фильтр по товару.
  - `is_main` (0/1) – фильтр по главному изображению.
- **Ответ**: `ActiveDataProvider` с моделями `ProductImage` (с загруженными связями `imageEntity`, `product`).

#### 5.2. GET /api/product-images/{productId}/{imageId}

Получить конкретную связь (стандартное view не переопределено, но в коде нет явного view? В actions не переопределён view, значит доступно по умолчанию: /api/product-images/{id}? Однако в контроллере переопределён update и delete с двумя параметрами, но стандартный view использует один параметр id. Скорее всего, стандартное view работает с одним id (первичный ключ). В коде не показано, но ActiveController по умолчанию использует id. Поэтому эндпоинт: GET /api/product-images/{id}. Но в update и delete используется составной ключ (product_id, image_id). Это нестандартно, так что нужно уточнить. Будем считать, что стандартные actions работают с одним параметром id (первичный ключ таблицы product_image). В остальном – стандартное поведение.

- **Требует авторизации**: Нет.
- **Ответ**: модель `ProductImage`.

#### 5.3. POST /api/product-images

Создать новую связь.

- **Требует авторизации**: Да (администратор).
- **Параметры body**:
  ```json
  {
    "product_id": 1,
    "image_id": 123,
    "title": "Название",
    "is_main": false
  }
  ```
- **Ответ при успехе**:
  ```json
  {
    "success": true,
    "message": "Изображение успешно привязано к товару",
    "data": { ... } // модель ProductImage
  }
  ```
- **Ошибки**: `422` – ошибки валидации.

#### 5.4. PUT /api/product-images/{productId}/{imageId}

Обновить связь (например, изменить is_main или title).

- **Требует авторизации**: Да (администратор).
- **Параметры пути**: `product_id`, `image_id` (составной ключ).
- **Параметры body**: любые поля модели `ProductImage`.
- **Ответ при успехе**:
  ```json
  {
    "success": true,
    "message": "Связь успешно обновлена",
    "data": { ... }
  }
  ```
- **Ошибки**: `404` – связь не найдена, `422` – ошибки валидации.

#### 5.5. DELETE /api/product-images/{productId}/{imageId}

Удалить связь.

- **Требует авторизации**: Да (администратор).
- **Параметры пути**: `product_id`, `image_id`.
- **Ответ**: `204 No Content` при успехе.

### 8. SiteController

Базовый контроллер для служебных запросов.

#### 8.1. GET /api/hello

### 9. UserController

Управление пользователями.

#### 9.1. GET /api/users

Список пользователей с фильтрацией и поиском.

- **Требует авторизации**: Нет? В коде аутентификация только на create/update/delete/assign-role/revoke-role, значит index доступен всем.
- **Параметры query**:
  - `role` (string) – фильтр по названию роли.
  - `q` (string) – поиск по username, email, name, surname, phone.
  - `page`, `per-page` – пагинация (по умолчанию 20).
- **Ответ**: `ActiveDataProvider` с пользователями (модели `User`).

#### 9.2. GET /api/users/{id}

Получить одного пользователя.

- **Требует авторизации**: Нет (доступно всем).
- **Ответ**: модель `User`.

#### 9.3. POST /api/users

Создать пользователя (администратор).

- **Требует авторизации**: Да (администратор).
- **Параметры (body)**: поля модели `User` (username, email, password_hash и т.д.). Пароль нужно передавать в открытом виде? Скорее всего, используется модель User, и там есть метод setPassword, так что ожидается поле password.
- **Ответ**: созданный пользователь.

#### 9.4. PUT /api/users/{id}

Обновить пользователя. Разрешено самому пользователю обновлять свой профиль, а также администратору – любого.

- **Требует авторизации**: Да (Bearer токен). Права: пользователь может редактировать себя, администратор – любого.
- **Параметры (body)**: обновляемые поля.
- **Ответ**: обновлённый пользователь.

#### 9.5. DELETE /api/users/{id}

Удалить пользователя (только администратор).

- **Требует авторизации**: Да (администратор).
- **Ответ**: 204.

#### 9.6. POST /api/users/{id}/roles

Назначить роль пользователю.

- **Требует авторизации**: Да (администратор).
- **Параметры body**:
  ```json
  {
    "roleId": 1
  }
  ```
  или
  ```json
  {
    "role": "admin"
  }
  ```
- **Ответ**:
  ```json
  {
    "success": true,
    "message": "Роль успешно назначена",
    "user": { ... } // обновлённый пользователь
  }
  ```

#### 9.7. DELETE /api/users/{id}/roles/{roleId}

Отозвать роль у пользователя.

- **Требует авторизации**: Да (администратор).
- **Параметры пути**: `id` – ID пользователя, `roleId` – ID роли.
- **Ответ**:
  ```json
  {
    "success": true,
    "message": "Роль успешно отозвана",
    "user": { ... }
  }
  ```

## Модели данных (сущности) и DTO

### Основные сущности

- **Product** – товар. Поля: id, title, short_description, long_description, info, article, price, in_stock, orders_count, main_image_id, manufacturer, country, created_at. Связи: mainImageEntity (ImageEntity), productCategories, categories, productImages.
- **Category** – категория.
- **ImageEntity** – изображение (хранит путь и URL).
- **ProductImage** – связь товара и изображения (промежуточная таблица с дополнительными полями: title, is_main).
- **User** – пользователь.
- **Role** – роль.
- **UserRole** – связь пользователя и роли.
- **CustomerRequest** – заявка клиента.
- **Parameter** – параметр сайта (ключ-значение).

### DTO для ответов

- **OkResponseDto**: `{ success: true, message: string, data: mixed }`
- **ErrorResponseDto**: `{ success: false, message: string, data: mixed }`
- **SigninResponsDto**: `{ token, tokenType, expiresIn, user }`
- **ProductResponseDto** – структура товара для вывода (но в основном используется сама модель Product).
- **UserResponseDto** – структура пользователя (используется в AuthController и UserController).
- **CategoryResponseDto**, **ProductImageResponseDto** и другие.

## Особенности реализации

- **Авторизация**: JWT токен генерируется через метод `generateAccessToken()` модели User. Время жизни задаётся параметром `jwtExpire` (по умолчанию 7 дней).
- **Права доступа**: проверяются через `checkAccess()` в контроллерах. Администраторы имеют доступ ко всем операциям записи, менеджеры – к заявкам.
- **Загрузка изображений**: в `CreateProductRequest` реализована загрузка изображений из base64. Файлы сохраняются в `@webroot/web/uploads/products/`.
- **Пагинация**: везде используется `ActiveDataProvider` с настройками.
- **CORS**: настроен для всех контроллеров через поведения.

## Коды ответов

- `200 OK` – успешный запрос.
- `201 Created` – создание ресурса (стандартное REST, но в некоторых переопределённых методах возвращается 200).
- `204 No Content` – успешное удаление.
- `400 Bad Request` – ошибка валидации запроса.
- `403 Forbidden` – недостаточно прав.
- `404 Not Found` – ресурс не найден.
- `422 Unprocessable Entity` – ошибка валидации данных (модели).
- `500 Internal Server Error` – внутренняя ошибка сервера.
